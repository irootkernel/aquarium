# Squad execution and exact evidence consumption

Use this contract from an explicitly invoked [Epic Squad](../skills/epic-squad/SKILL.md).
The [collaboration contract](epic-squad-collaboration.md) owns role independence,
correction depth and authority. Squad uses its actual `aquarium:epic-squad` owner.
Its Goal and Validation consumers include integration, recovery and scoped
correction/closeout routing in source. TASK-151 owns installed observations.

## Select an exact definition before work

Use the [adaptive selection and suitability flow](adaptive-execution.md). The
optional packaged sources are `assets/adaptive/reusable/squad-goal.yaml` and
`squad-validation.yaml`, each with its sibling `.binding.json`. They are templates,
not managed files or pre-admitted definitions. A target repository need not have
Squad copies under `.podway/procedures`.

During read-only selection, inspect these installed package bytes and their
binding. Under the approved definition-preparation grant, copy the selected pair
to a disclosed ignored local root. Supply an ordinary `procedure_plan` adaptation
with `kind=adapt`, the copied source as its exact `base`, the complete source as
`document`, and its binding without `procedure` as `mapping`. Map every original
criterion part to an appropriate existing obligation. Explain why the
Handler-owned managed Goal/Validation source cannot supply Squad's distinct
planning and composition boundaries. Preserve actual adopted customizations.

Run the existing preparation helper with that ordinary assignment. Obtain the
actual independent exact suitability assessment, including any new semantic
claims requested by the helper, and retain its self-contained qualified bundle
before native start. A synthetic qualification fixture, source preview or a
binding file supplies no actual agent assessment. Reuse a later retained bundle
only with its original exact suitability and current fit evidence. Keep all
legacy source/version mappings, binding bytes and admitted snapshots unchanged.

The supplied Goal source is a member/remediation planning template. Use the
retained Validation closeout scope for final lifecycle work when adequate; adapt
only for a missing boundary. Do not recall a retired Task team for bookkeeping.
The supplied Goal source exposes Task plan production, TE/panel intake, current
Task-plan basis, scoped EE plan intake and current Epic-plan basis before Writer
delivery. Candidate intake, complete correction classification, local correction,
affected judgment, evidence recovery, current composition, exact acceptance and
finalization have separate native boundaries. The Validation source independently
assesses the assembled Epic. All Decisions belong to the Coordinator.

A completed assessment Action records an actual assessment, including `rework` or
`evidence-needed`. It does not declare success. Native rework invalidates its
selected records; preserve useful original external artifacts only after current
applicability checks and re-record them under fresh fences.

## Consume direct assignments

Use `manage_adaptive_procedure.py context --entrypoint epic-squad` with the exact
retained definition, ordinary qualification and current session. Squad returns
`dispatches`, one ordinary v3 assignment per direct role/scope, while `dispatch`
remains null. The Coordinator creates distinct native instances and joins their
actual results at the one native cursor. TE, independent TO reviewers and EE
never become one producer merely because they share an Action.

Set `target.squad.risk` to the assessed `standard` or `elevated` scope. The default
first Task panel contains TE plus one or two independent TOs; candidate intake
also includes EE's distinct Task contribution. Integration uses EE plus at least
two fresh non-authoring TOs. Keep this first-panel risk unchanged when a later
correction needs a different assessment depth.

Before affected dispatch, record the actual `target.squad.correction` with its
`id`, current `phase`, `depth`, `epic_scope_changed` boolean and classification
`basis`, plus `original_assessments` containing the ordinary references for the
corrected unresolved source judgments. Use `primary-only` for a nonbehavioral
change requiring independent judgment, `bounded` for primary plus one TO, or `elevated` for primary plus two TOs under
the collaboration correction table. TE is primary for Task corrections; EE is
primary for integration, closeout and correction-group work. Task corrections
with cross-Epic effects also include EE. An EE's own unresolved finding requires
EE judgment even when the correction has no cross-Epic impact. Other unresolved
original assessors also participate in their own corrected obligations; do not
recall unrelated first-panel members. Resolve unknown depth or impact before
dispatch. The same role derivation consumes the classification retained in each
affected closure's verification. Local eligible closure requires no new panel.

Each affected closure must identify its actual original source in that
classification. Current delta evidence comes from the original public producer
or a supported ordinary replacement in the same role. A replacement report's
`native.replaces` identifies the original `assessment` ID, original `public_handle` and current
recovery `basis`. It independently covers the original criteria, gaps and current
delta under the existing authority. Keep all original reports. No private history,
configuration proof, owner registry or permanent physical-agent identity is
required; current scope, coverage and independence checks still apply.

For renamed/custom evaluator placements, `procedure_plan.squad_phases` maps the
actual placement to its Task plan, Epic plan, Task result, integration or affected
result scope before preparation. Unmapped evaluator scopes stop; node spelling
cannot silently replace TE with EE or discard a panel. The ordinary machine roles
and report schema identifiers remain unchanged.

Optional `target.squad.support_assignments` maps an actual non-writing executor
placement to a factual support scope. It yields a Support Operator assignment
with no verdict, closure, Writer, index or progression authority. It cannot
replace a required reviewer or turn a work placement into support. Evaluator and
review assignments keep project files read-only; separately assigned non-mutating
checks or supported native assistance may be permitted. These scoped Squad
assignments do not broaden the generic `goal-evaluator` skill.

On a repeated native attempt, restore `target.squad.reentry` with that exact
`attempt_id`, the invalidation/correction `basis`, due `assessments` as
`[display_role, scope]` pairs, and readable `original_evidence`. An empty due list
means current re-recording of applicable originals, not a new assessment. Missing
or mismatched recovery context stops dispatch. Restore the exact owner, selected
route, findings, closures, pending operations and consumed/remaining grants;
never create a second goal or replay a successful commit.

At an observed repeated native plan attempt, a matching Task-plan or Epic-plan
correction classification selects the affected scopes and correction depth at
the existing plan assessment placement. The requested reentry scopes must match
that actual dispatch. A caller's reentry claim cannot change first-attempt plan
coverage. Preserve the first plan reports with current applicability and settle
their negative parts or named findings using the actual new affected reports.
Both current plan compositions remain due at commit; never replace an original
negative report to make the plan pass.

## Verify a current composition

At a composition placement, supply its basis in
`target.squad.compositions[<actual-node>]`. The mapped consumer returns
`composition-required` while that basis is absent. The source declares each
native check's actual operation ID and digest; use those declarations when
recording the returned current facts.

The composition carries `phase`, exact `target`, complete original `criteria`,
original `assessments`, `closures`, due `checks` and `pending` counts. The invocation
supplies the current `plan` and `candidate`, original plan/implementation `authors`,
risk and `required_checks` in `target.squad`. The check inventory may map each
phase to its own due IDs, so planning readback does not demand future product
tests. An explicit empty list means no check is due; a missing inventory stays
unknown. The consumer resolves original criterion parts from the canonical
requirement sources. Current summaries cannot
fill omitted original assessment coverage.

Each assessment reference retains its unique original `id`, `role`, `producer`,
`scope`, reviewed `target`, applicability and basis, plus `path`, `sha256` and
`bytes` for the complete readable ordinary report. The report retains its actual
schema, human role, public producer handle, plan/candidate target, original verdict
and criterion rows. Current phases require the actual TE/panel and EE scopes.
Distinct roles require distinct non-authoring instances. Explicit `future_criteria`
retain global future rows outside the due Task basis; a passing scoped checkpoint
never relabels the report's global verdict as an Epic pass.

For Task-plan, Epic-plan, scoped contribution and affected assessments, the
report may retain future global states within the same original criterion. Its
`checkpoint_assessment` then identifies the actual assessment `phase`, `state`,
`basis` and complete due `criteria` with their original part IDs, alongside the
actual `checkpoint_result`. The consumer uses those per-part judgments for the
due scope and retains `original_criteria` and `original_verdicts`. Each global
negative part that the scoped judgment resolves needs its original readable
`applicability` explanation or `reason`. A summary or passing checkpoint alone
cannot fill missing part coverage. Missing, unknown or
negative due proof blocks readiness; future implementation need not become
globally met for a plan to pass.
Task-result and integration negatives still require their exact eligible closure
or affected assessment; a met checkpoint row cannot replace that router.

A source-bound `procedure_plan.member_scope` may distinguish current member
readiness from unverified whole-Epic source states. The map retains every
original criterion/part, source path and pin, with readable current, later and
separately gated duties under the adaptive preparation contract. Both independent
Task-plan and Epic-plan bases must cover this exact map and current plan.
Native callers retain those bases in `target.squad.compositions`; the pure
commit caller supplies its existing `plan_compositions`. Ordinary opt-out needs
the same plan judgments, without a native or prepared-definition prerequisite.

For this matching `member-task` only, each plan/result report's ordinary target
and each composition carry the same `member_scope`. Actual newly reconciled
TE/TO Task-result and EE contribution checkpoints retain the original canonical
criterion/part pairs. They assess all duties due for this member while the
reports retain their original global criteria and verdicts. An original
`unverified` part may be met for the current member only when its original
assessment explains the future applicability and the map includes matching
later or gated duties. An original unmet obligation still follows its exact
closure/affected-assessment route. Current due unknowns, failed checks, required
findings and unidentified negative verdicts remain blocking. A core-only milestone or an unchanged
inconclusive conservative projection cannot become member completion.

The returned member basis identifies the scope of current counts and member Goal
achievement; `original_criteria` and `original_verdicts` preserve global states.
Integration, correction-group and closeout continue to consume whole original
obligations. Member readiness does not establish final Epic completion, actual
acceptance, a commit grant or native finalization. Absent-scope callers retain
their existing consumption rules.

When an original Markdown source becomes an approved lifecycle deliverable,
retain its pin and use the existing approved-original-source recovery path.
Native continuation threads its validated reader into composition and both plan
bases, preserving checkpoint/session/attempt/goal/trace and definition fences.
Pure commit may carry the existing `target.applied_source_context`: readable
original capture/Git references, exact proposal/approval or continuous change
history, approved applied images and ordinary work provenance. This pure
consumer requires no native observation or checkpoint; the native wrapper and
Coordinator retain their actual continuity checks independently. Before and after
consumption, revalidate the emitted context against the original bytes, actual
approval, full affected-source chain and current postimages. Strict pre-start
source checks remain. Lifecycle changes still require proof that assessments
apply to the current candidate, plus product review, acceptance and the matching
unconsumed grant. Original-source recovery waives none of these requirements.

Criterion parts retain all four ordinary states, including `not-applicable`.
Each such part needs its readable applicability `basis` or `reason`, in the
original assessment of that part and in the current composition. The canonical
source, original part identity, exact report target and current applicability
remain required. A justified conditional branch can be ready while staying
`not-applicable`; a bare label cannot remove a mandatory part or a source gap.
The consumer checks coverage and evidence structure. Independent assessments
establish the meaning of the applicability reason.

A changed reviewed target needs `applicability=preserved` and a digest-bound
`applicability_evidence` artifact identifying `before`, `after`, passing outcome,
`preserved_scope`, actual checks and `unknown_impact=false`. Unknown or unreadable
applicability cannot pass. Check references have stable due IDs and complete
original receipts with exact target, command and outcome. Retain earlier failures
and explain actual execution/reuse; the consumer does not execute checks.

A plain due check ID continues to accept its actual current-target passing
receipt. To reuse an older passing receipt, its due inventory entry identifies
`id`, `execution=reusable` and the existing verification-policy `basis` that
permits reuse. An exact-current gate uses `execution=current-target`; the
consumer never infers that policy from a command name or prose.

The older check reference keeps its original identity and adds
`applicability=preserved` with digest-bound `applicability_evidence`. That proof
binds `source_check`, `check_id`, before/after targets, passing outcome,
`preserved_scope`, `unknown_impact=false` and basis. Its `before_context` and
`after_context` retain comparable `command`, `coverage`, `inputs`, `dependencies`
and `environment`; the command must match the original receipt. Changed or
unknown applicability and exact-current gates require current execution. Keep
failures and earlier receipts as history without relabeling them as fresh runs.

A closure names the source assessment and either its criterion/part or original
`finding` ID, before/after targets, original owner, disposition and basis. Its digest-bound `verification` artifact
retains the finite delta, actual checks and `unresolved_judgment=false`.
`local-verified-fix` additionally requires actual local eligibility.
`affected-assessment` retains the actual `correction` classification and current
independent delta reports, with the required primary and correction reviewers.
Its phase identifies the original judgment: a correction-group classification
may carry forward to integration or closeout, and integration may carry forward
to closeout, with verified current applicability. Preserve source priorities
and original negative rows. Coordinator-authored semantic changes still need
non-authoring confirmation under the collaboration contract.

An assessment may report a named non-feature finding while all feature parts
are met. Preserve every original `findings` row and verdict. A finite local
closure can settle that original ID; an affected assessment must explicitly
resolve it in its current finding rows. Neither closure removes another finding
or a negative criterion part. Passing checkpoint metadata cannot erase a named
current finding. Unidentified negatives remain unresolved. Attribute clearly
outside-scope work with `future_findings` and the original row's `applicability`,
or its explicit `scope=future` marker and basis. Keep those original rows visible.
Generic finding justification alone establishes no outside-scope applicability.

Retain optional advice without making it a mandatory correction. The original
reviewer can mark it with `priority=optional`, `state=optional` or
`state=nonblocking`, or `blocking=false`. A Low priority alone is not such a
marker. Explicit required/blocking findings, negative criterion parts and
unidentified mandatory judgments remain open until their actual obligations are
settled; optional advice needs no fabricated closure or future-scope label.

Record `pending.local`, `low`, `blocking` and `judgment` independently. Ready
composition requires every current mandatory part met or justifiably
`not-applicable`, all due check receipts, complete independent coverage and zero
pending obligations. The returned `new_evaluator_verdict` stays null. Its current native values describe the
verified composition, never a fictional fresh TE/EE pass. Plan readiness remains
separate from Goal achievement.

A `correction-group` composition retains the originating integration EE audit
and its exact negative group obligations, current checks and eligible closures.
It follows the owning validation-remediation Task/Epic route. Local closure
does not recall the whole integration panel; an affected judgment uses EE as
primary and only the reviewers due for that correction depth. A generic EE pass
cannot replace the source audit. Ready group composition permits only the scoped correction
handoff: `whole_epic_confirmation` stays `pending`, and its native Goal outcome
stays `not-achieved`. First assessments remain due at their original boundaries.

## Native integration and recovery

The current packaged Goal template uses version 3 and Validation uses version 5. A selected retained
older bundle keeps its exact source, binding and original contract. Never replace
its snapshot with the new package bytes. A genuine missing boundary follows the
existing qualified successor/consent path.

Validation selects integration, correction-group or closeout scope explicitly.
First assembled integration requires the actual EE and two fresh nonauthoring TO
reports plus Coordinator product review; Task passes cannot supply it. A ready
integration records its results before preparing record-only final closeout.
A ready correction group reaches an intermediate scoped commit in that same
Validation session. It remains `not-achieved` with whole-Epic confirmation
`pending`. Verify the actual commit and consumed correction grant, then rework
the current composition with preserved original reports, closures and applicable
checks. Do not create or finalize a nested Goal. Only current whole-Epic evidence
and actual user acceptance permit the conditional final closeout.

Both executed integration and scoped restoration produce `integration-basis`,
which reaches classification and current composition as an original obligation
producer. A context brief cannot replace the EE/two-TO reports. For final
closeout, prepare the exact record changes, restore that basis, and select the
`closeout` correction route through `assess-affected`. Supply the existing
`epic-closeout` correction classification with the original EE reference and
any unresolved original owner references. Keep the full first panel in
`integration-basis`; unchanged TO judgments do not become affected assignments.
EE is primary with only the additional roles actually due. Its actual
`affected-epic` report reaches strict closeout composition alongside the original
integration panel. Completeness and current applicability are distinct from
passage: an actual negative report remains established and unresolved, with its
original findings, verdict and real current counts. Correct its due obligations;
do not retrieve another EE merely to replace a negative judgment.

An unchanged exact candidate may explicitly reuse demonstrably applicable
substantive assessment. After actual first closeout EE coverage, an eligible
meaning-preserving record delta may retain that judgment without routine EE
recall. The older reference keeps `applicability=preserved`; its digest-bound
proof includes the full `source_assessment` reference without applicability
metadata, before/after targets, `preserved_scope=affected-epic`, actual checks,
basis and delta. Require `unknown_impact=false`, `local_eligible=true`,
`record_only=true`, `meaning_preserved=true` and `unresolved_judgment=false`.
Establish substantive first closeout purpose from the actual report's original
work context or its referenced ordinary closeout EE assignment, with the reviewed
candidate aligned. Generic `affected-epic` assignment scope or checkpoint phase
alone cannot distinguish closeout from other affected Epic work. Honor contrary
original phase or work-unit provenance, even when a report claims closeout. An
original semantic `integration` assignment scope cannot supply first closeout
coverage for a moved candidate, even if copied work-unit metadata says closeout.
Ordinary assignments may be text, inline structured input or a referenced file;
optional assignment provenance adds no universal file or byte-count requirement
for unchanged exact-candidate reuse. Verify available declared file identity, and
leave missing first coverage open when required provenance is unavailable. No
new field is mandatory for every ordinary report. Relabelling an old integration
reference cannot establish missing first closeout review.
Unknown impact, changed normative meaning or missing first coverage stays open
for its due assessment. Complete current checks and Coordinator product judgment,
then ask once for actual acceptance of the final presented candidate.

The integration EE may continue as final EE; a supported same-role replacement
or fresh independent EE is also permitted. An integration TO cannot fill the EE
role by changing a label. Distinct original roles and nonauthoring requirements
remain. Record-only edits require no invented product tests.

Keep a settled affected closure's original classification, reports, owner,
verification and before/after targets unchanged. An Epic correction-group
classification may carry forward to integration or closeout, and integration
may carry forward to closeout; this does not supply missing first coverage.
At the same candidate, its actual confirmed closure remains valid. For a later
candidate, add `applicability=preserved` and digest-bound
`applicability_evidence` to the closure. The proof binds the full `source_closure`
without applicability metadata, exact original confirmation references in
`confirmations`, the closure's original after target as `before`, current `after`,
original classification phase as `preserved_scope` and actual `current_scope`.
It also carries checks, basis, delta, `unknown_impact=false`,
`meaning_preserved=true` and `unresolved_judgment=false`. A local record delta
may use `local_eligible=true` and `record_only=true`. Across a behavioral change,
bind equal, nonempty `before_context` and `after_context` objects for the settled
obligation's `inputs`, `coverage`, `dependencies`, `environment` and `judgment`,
and name its actual current passed check IDs in `checks`. This establishes the
closed obligation's preservation across the cumulative delta. Supplied context
must agree even for a record delta. The separate first-closeout coverage rule
above remains required. Each confirmation retains its original judgment on the
settled repair, with its own current source
applicability; it is not relabelled as a new closeout assessment. Missing original
reports, missing owners, stale proofs, failed confirmation and changed or unknown
scope cannot carry a closure. Negative history remains readable after settlement.

At native composition intake, `composition-evidence=established` means the strict
consumer returned an actual composition, including unresolved results with their
real counts. Missing coverage, failed due checks, unreadable evidence or other
consumption errors return a separate `composition_error`: retain its exact code,
message, details, phase, target and input basis. Record `unavailable`, an
`inconclusive` check and `not-achieved`; leave unestablished criterion/pending
counts absent. These counts are conditionally required only for established
compositions. An absent count never equals zero. The negative Action can complete
and follow its evidence-recovery Decision, while every success route still needs
actual zero counts and a passing current check. The strict composition and commit
consumers continue to reject the underlying error. No provider/global row counts
are inferred from it.

On resume, use the existing native session and public role/operation handles.
Recover complete missing output from that operation before replacement or
redispatch. Preserve original reports, classification, closure verification,
check execution/applicability, deferred-work reasons, source/binding, exact
candidate, configuration and consumed/remaining grants. Reconcile each pending
request with its current owner; a role waiting for Coordinator action returns
the actionable request instead of holding an in-turn circular wait. An overrun
needs a concrete observation and next owner, not automatic cancellation.

Other settled Tasks and merely retired teams are not automatically recalled.
Then select an adequately qualified successor Validation, restore the original
assembled audit as `integration-basis`, and obtain only the affected current
assessments/checks plus missing first coverage. Preserve each consumed grant and
successful commit without replay.

For that successor, select the adequate Validation `integration` scope, not
`correction-group`. Restore actual settled Task delivery, original assembled
EE/two-TO reports, current applicability, retained closures and due checks. The
existing `deliver-work` and `assess-integration` placements record these real
results; entering a node does not itself launch an agent. Where mapped reentry

record with invented work to obtain a reentry attempt. If the selected retained

The roadmap state describes the actual work;
a session transition cannot silently reopen or re-complete a Task.

Before helper retirement collect actual results, findings, configuration and

## Additional reviews and commits

`authority.review.route=not-required` is Squad's explicit absence of an additional
technical-review operation. It creates no waiver, provider identity or ordinal,
and waives no collaboration assessment. Legacy callers reject it. A selected
Mulgae, Herdr or Subagent Review operation keeps its own team, transmission,
ordinal, current result and recovery contract. The minimal Squad templates need
an adequately qualified review-control extension for such a selected route;
never force them through a misleading `not-required` or waiver record.

For a selected extra route, retain `technical_review` with its original target,
verdict, authority and digest-bound evidence, together with the actual provider
operation, ordinal and assessment kind. Its current `completion` records unmet,
unverified, blocking, local and Low counts separately; each must be zero.

When the provider-reviewed target predates the accepted target, carry a
`local_settlement` artifact with exact before/after targets, original source
reference/verdict, `review-predates-local-correction` coverage, permitted delta,
whole-set local eligibility and current verification. Missing, mismatched,
nonlocal or unresolved bridges stop commit consumption. Preserve the original
provider result and ordinal; an eligible verified delta needs no new provider
call solely to match the final hash.

The Coordinator supplies the ordinary assignment, original composition, exact
acceptance and selected grant to the pure consumer:

```bash
python3 <installed-shared>/adaptive_squad.py \
  --repository <worktree> --handoff <ordinary-squad-commit-input.json>
```

It performs no native discovery or commit. `authority.commit_grants` retains the
approved distinct grants with ID, kind, owner, Epic/Task and actual consumption
state. The chosen `grant` must equal one unconsumed scoped entry and match
`target.squad.work_unit_kind`: member, pre-validation correction, validation
correction or final Epic closeout. Acceptance binds its source and authority to
the exact current target, Coordinator product review,
and lifecycle, record and release-note decisions. Member and correction grants
cannot substitute for each other or for conditional closeout. Final Epic closeout
requires actual user acceptance and its matching conditional grant.

The completion phase must also match that work unit: member Task and
pre-validation remediation use `task-result`, validation remediation uses
`correction-group`, and final closeout uses `epic-closeout`. An integration
assessment cannot substitute for a member's Task-result assessment.

When a selected whole-Epic technical review is still pending at a correction
commit, retain its selected route and supply the existing Coordinator scope
decision as digest-bound `review_boundary` evidence. That record identifies the
current target, `phase=correction-group`, route, actual `due` boolean, authority,
basis and `whole_epic_confirmation=pending`. Reuse an ordinary decision or
handoff artifact; this requires no separate approval or report cycle. Unknown
boundaries stop consumption. With `due=false`, the current provider operation
is `not-due` and its ordinal is absent. Before the first review, `source_review`
is null; afterward it retains the original route, operation, ordinal, target,
verdict, authority and evidence independently of current group coverage. A
review actually due at this group retains the selected-provider requirements.

Member and pre-validation correction handoffs also carry both actual
`plan_compositions`. Their unchanged original plan reports and checks may remain
applicable; an opted-out path cannot omit either plan scope.

Pass the verified result, complete original review/closure/check references,
accepted source composition and session-relative continuation to
[task-commit](../skills/task-commit/SKILL.md). That skill owns staging, identity,
Lore, Sanho, the one commit and post-hook comparison. Its result returns to Squad
for native finalization. A successful commit awaiting finalization is verified
and resumed without another commit. No grant supplies installation or publication
implicitly.

plan, evidence, grant and overall acceptance obligations through ordinary reports.
