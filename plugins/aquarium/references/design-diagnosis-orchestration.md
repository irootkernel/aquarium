# Design and diagnosis orchestration

Design and War-room version `11` use ordinary Actions under the
[v2 contract](ordinary-agent-orchestration.md). Native roles use the current
Primary harness without role-snapshot, private-history or configuration
qualification. Admitted formal snapshots keep their original
[v1 contract](formal-agent-orchestration-v1.md) and receipt requirements.

## Original evidence and phase checkpoints

Supply original requirements, current artifacts, checks, actual authority and
available public handles. Design uses the [mapped adaptive consumer](adaptive-execution.md#design-entrypoints) for all three entrypoints and exact prepared/running recovery. Design groups context/discovery, draft/challenge/quality
and approved application. War-room groups baseline/investigation,
proposal/quality and approved documentation or no-change delivery. The Primary
records simple operations and Decisions; the report-only Judge independently
assesses each coherent phase. Final assembly adds no Worker or Judge cycle when
a complete final assessment remains applicable to unchanged candidate, criteria
and checks; otherwise obtain fresh affected assessment without relabeling a phase
report as final.

Every phase report retains all original criterion rows, the actual global
verdict and unmet/unverified counts. It also includes current phase obligations
and applicable parent constraints. `judge-checkpoint-result` verifies actual phase work from
direct evidence. Report completeness alone cannot establish correction or
application success. A passing phase checkpoint may coexist with remaining
original workflow gaps; it never establishes whole-goal achievement.

Quality checkpoints verify faithful original QA output and local adjudication,
including negative artifact verdicts, unresolved issues and original correction
owners. Raw QA `FAIL` or `REVISE` with adjudicable output remains operation
`pass`. A faithful negative report reaches the original `decide-quality` router:
Design discovery findings return to discovery, other draft/challenge/trust
findings to drafting; War-room baseline/reproduction findings return to baseline,
classification/proposal/trust findings through investigation. Failed or missing
operation evidence returns through quality. Neither checkpoint may erase rows
or record false zero counts to reach the router.

Investigation checkpoints preserve evidence-backed `established`, `no-work`,
`investigate-more` and `blocked` recommendations. The Primary retains the cause
and scope Decisions, with each option constrained to the current Judge
recommendation. No-work requires evidence that expected behavior holds;
unexplained or unreproduced symptoms remain incomplete. Established causes may
produce Task, Epic or incomplete proposals; blocked investigations produce an
incomplete proposal. All supported terminal proposals retain quality, actual
approval, document or no-change verification and final assessment. An approved
incomplete diagnosis is a diagnostic deliverable and never a fixed-defect claim.

## Effects and exact approval

Inapplicable reports return to their current Judge. Actual failed phase
obligations enter a correction record; missing evidence enters a separate
evidence record. Each local authority Decision requires actual applicable
unconsumed authority for its exact operation, target and owner. A negative
verdict cannot grant or renew checks, providers, clipboard access, document
application, installation, implementation, staging, commit or publication.
Uncovered work stops at its local authority gate. Discovery evidence gaps select
`capture-context` or `discover`; investigation gaps select `capture-baseline` or
`investigate`. Each grouped route requires both its exact owner and passing
existing effect authority. Other earlier owners use an explicitly authorized
manual rework operation with a supported target.

The original `approve-diff` gate binds the complete actual user-approved
proposal or no-change and unchanged target snapshots. Before writing, the
Primary supplies that exact authority and the application Worker rechecks it.
`application-approval-result` must pass before final evidence preparation.
Application/documentation correction returns to Design draft or War-room
investigation, then the original challenge where applicable, quality and actual
exact-diff approval. Evidence-only re-entry may verify unchanged approved bytes
or no-change; changed proposal or target bytes require this original reapproval
route before any write. Judge passage never grants document application.

Preserve the [Ouroboros leaf contract](ouroboros-integration.md) and applicable
[Design Gates](design-gates.md). Workers may use only authorized upstream leaf
capabilities; no `auto`, `run`, `ralph`, `evolve`, substitute implementation or
nested workflow session. The Primary retains actual PM clipboard authority.
Non-Git `new-project` uses the same semantic evidence and exact approval with
explicit Podway inapplicability; never initialize Git or Podway implicitly.
Design Gates apply only to an already enrolled registry.

## Final assessment and retained history

The Primary final evidence index and applicable independent Judge assessment precede the
original native `assess-goal`. Achievement requires the exact `achieved` outcome,
pass verdict, zero mandatory unmet/unverified rows and fresh assessments of
every original native criterion. Phase labels, inherited verdicts, provider zero
or unsupported manual claims cannot prove success. Preserve honest
`not-achieved` and `superseded` outcomes and separate document delivery from
product implementation and commit/publication authority.

Use actual public native results and preserve unavailable telemetry as unknown.
Local structure and synthetic fixtures do not prove installed startup, rework,
recovery or upgrade. Follow the target repository's verification environment
policy for installation-dependent behavior and keep actual Master acceptance
separate. Ordinary recovery reconciles known work before
replay and settles mutating Workers before replacement, without requiring full
executor history.
