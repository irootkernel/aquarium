# Epic Validator

Read [commit-attribution.md](../../references/commit-attribution.md) for message formatting and change origins, within this skill's existing effect boundaries.

Read [review-routing-contract.md](../../references/review-routing-contract.md) for route selection, route-specific readiness, evidence combinations, recovery, and assessment ordinals. Read [review-intent-contract.md](../../references/review-intent-contract.md) for the shared Review Brief and criterion-level completion assessment. Read [mulgae-review-contract.md](../../references/mulgae-review-contract.md) only when the selected review route is `mulgae`.

Validate a completed epic independently of how it was delivered. Run no more than three work-unit assessments and one remediation confirmation, stop early on a clean or locally settled result, and require user direction only for necessary provider reassessment beyond ordinal four. Read [release-notes.md](../../references/release-notes.md). Do not invoke `$aquarium:task-handler`, `$aquarium:epic-handler`, or their phase skills. Invoke `$aquarium:independent-review` or `$aquarium:herdr-review` only for its explicitly selected and approved route.

Always read [evidence-residency.md](../../references/evidence-residency.md), [finding-disposition.md](../../references/finding-disposition.md), [documentation-governance.md](../../references/documentation-governance.md), and [epic-execution-sot.md](../../references/epic-execution-sot.md). On the Podway path also read [procedure-node-contracts.md](../../references/procedure-node-contracts.md).

Use Podway by default. Exclude it only when the current user explicitly opts this validation out before its managed session starts or a higher-priority instruction prohibits it. For an opted-out validation, do not inspect Podway, load `$use-podway`, or read [podway-integration.md](../../references/podway-integration.md), and do not carry the opt-out into a later workflow.

Otherwise read the Podway contract and use one `aquarium-validation-v2` session for this exact cold-validation lifecycle. Podway records each bounded pass and user disposition; the roadmap and current implementation remain the semantic authority. A session created from an earlier managed Procedure version keeps its immutable snapshot and is not migrated in place.

Create a Codex goal only on explicit user request under its tool contract, whether Podway is active or opted out. Continue an existing authorized Codex goal through audit, remediation, and confirmation within its own scope. Remediation groups organize the work; they do not create separate Codex goals or Podway sessions.

Read [validation-orchestration.md](../../references/validation-orchestration.md) for ordinary v2 roles. A fresh cold Judge audits original criteria and artifacts directly; internal validation retains its logical Epic Judge when supported. Audit and re-audit are direct report-only Judge work. Before dispatch, the Primary or an authorized Worker executes due repository checks and supplies actual results; the Judge does not run checks. The Primary records the aggregate audit and check result. Workers deliver correction groups with checks; the Primary accepts and verifies their authorized commits before re-audit. Current sources require no native qualification; admitted formal sessions retain their original v1 contracts.

## Settle corrections before requesting another review

Classify the complete current issue set first. Local settlement is available only when every current blocking obligation is locally eligible; a mixed nonlocal set keeps its original rework, confirmation or user-direction route as a whole, including the complete frozen finding and criterion set. Apply [finding-disposition.md](../../references/finding-disposition.md#decide-whether-a-correction-needs-another-review) before treating priority or a negative completion row as a provider-rework obligation. A `local-verified-fix` keeps its effective priority and is corrected and verified within the existing envelope without another approval or provider ordinal, including in confirmation-only mode. Preserve the original review and criterion rows, then bind current completion to the exact locally verified delta and the required final Judge assessment. Execution incidents follow [review-contract.md](../../references/review-contract.md#reviewer-instruction-deviations); preserve usable evidence and repair only the affected guarantee under existing authority. When another provider assessment is genuinely required, run it on the selected route within the remaining grant without asking again. Only uncovered effects or exhausted necessary review authority require new approval.

## Establish the Validation Contract

Require one mutable Git repository, one canonical roadmap path inside it, and exactly one epic ID present in that roadmap. Reject task-only requests, multiple epics, and requests without one canonical roadmap epic identity.

Before requesting approval:

1. Read instructions, the epic, complete member-task set, `docs/README.md`, roadmap and canonical-document links, any active dossier, linked canonical outcomes, decisions, contracts, operations runbooks, tests, documentation, and required or generated artifacts. For an active or in-review epic, use the dossier when one exists. When no dossier is declared, resolve the shared composite execution SOT and disclose its source paths and requirement owners in the validation envelope; the absence itself is not a validation gap after an explicit waiver. Treat a declared dossier whose link cannot be resolved as a broken declared link and stop on the resulting semantic gap. Apply the shared dossier-waiver flow before validating an active or in-review epic. When that work meets a creation threshold, obtain the user's choice to consider a waiver before preparing the final envelope; choosing dossier creation stops this workflow with the exact work-definition continuation.
   For a completed epic, validate acceptance from current canonical outcomes and repository-defined historical sources without recreating a deleted dossier; enforce dossier disposition or named outcome fields only when repository authority declares that lifecycle. A retained shared dossier is valid while another consumer epic remains non-terminal or still canonically references it; verify those consumers before reporting closeout residue. Report the exact missing semantic owner or broken declared link.
2. Confirm every member task is in a roadmap-defined successful state and its implementation has a committed evidence-backed baseline. The epic itself may be in review or a successful state. When a member task is incomplete, stop and report which handler the user should run; never invoke it here.
3. Inspect branch, upstream, HEAD, staged, unstaged, untracked, and conflicted state. Record the validation baseline and separate epic-owned residue from unrelated work. Stop when the epic baseline is uncommitted or cannot be isolated safely.
4. Discover repository-native verification, Gaori, `$use-gaori`, documentation synchronization, Sanho, `$use-sanho`, lifecycle, commit guidance, and only the selected review route's prerequisites. Select `mulgae` by default or an explicitly approved `herdr`, `independent-review`, or `waived` route. Record the exact committed target, explicit Herdr reviewer or waiver authority, and assurance limit. Treat each CLI, repository configuration, project MCP, and agent skill as independent state. Inspect explicit external dependencies read-only and record repository, canonical identity, exact revision, lifecycle, dirty state, evidence, and owner.
5. Inspect the current goal and stop rather than replace a different unfinished goal.
6. Honor an explicit pre-session opt-out without Podway discovery and ignore every Podway readiness or session state. Otherwise apply the shared contract's readiness and session checks. On degraded readiness, route a missing or unsupported global Podway CLI or `use-podway` skill to `$aquarium:dev-setup-global`; route repository configuration or managed-Procedure gaps to `$aquarium:dev-setup`; then stop and ask the user to choose the exact routed repair or an explicit opt-out for this validation.
   - Resume a managed validation session matching this epic and baseline. Only when starting a different session, present the existing session and obtain the shared contract's explicit preserve, lifecycle, delete, or eligible-replace choice. Never route by skill owner or describe the choice as setup repair.
   - A disposed terminal session with verified handoff evidence and a current `session.start_replace` template becomes an exact successor candidate. Include its automatic archival in the validation envelope and, after approval, execute the template's current plain `start` argv without a separate reset before re-observing and beginning the prepared validation session.

Present one bounded validation envelope covering the resolved execution SOT, direct audit, authorized checks, the selected review route and disclosed source transmission, the three-work-unit plus one-remediation-confirmation maximum, shared-policy remediation, canonical changes, conditional evidence promotion, isolated staging, exact restaging of already staged affected paths, and one commit per actual remediation or lifecycle diff. Ask once for explicit approval. For an active or in-review epic with no dossier declared, require that approval to waive the dossier explicitly; generic approval is insufficient. When that work meets a creation threshold, this is the second confirmation after the user chose to consider a waiver. Exclude new unplanned files and any post-ordinal-four correction requiring another provider assessment, or that assessment, unless separately authorized. Eligible local corrections and ordinary Low settlement remain inside the approved envelope. A clean validation with no canonical change creates no repository diff or validation-record commit.

Approval does not cover new product requirements, another repository, amend, push, PR or release changes, live rollout, destructive actions, installation, or unrelated staging.

By default the envelope must cover creating or resuming the prepared validation session, the separate fenced `begin`, bounded evidence recording, decisions, rework, goal assessment, terminal completion, and any supported terminal disposition. Treat approval that explicitly omits Podway as approval of the same envelope without those operations.

Accept that opt-out only before the first managed-session mutation. Afterward classify every stop or opt-out request through the shared `Handle In-Progress Stop Requests` flow; never assume pause, cancel, reset, or an in-place switch to non-Podway execution. Never reset or replace another session automatically.

Do not create a goal, edit files, invoke providers, stage, commit, or alter external state before approval.

When a selected check uses Gaori, read [gaori-integration.md](../../references/gaori-integration.md). Require the agent performing the check to load and follow the installed `$use-gaori` skill before transport selection or execution, then consume the exact command result and evidence through that contract, including prerequisite routing and optional direct-command fallback.

Before each review, bind the effective route to the approved envelope or an explicit later route-change authority and preserve the immediately preceding route and operation, lifecycle state, prior ordinal, assessment kind, finding lineage, remaining authority, and corrected target. Record the caller-supplied route-binding result only after comparing those values with the requested direction, effective route, goal revision, current ordinal, and assessment kind; `resume-current` fails when the effective provider differs from the preceding unsettled provider, and earlier change authority cannot authorize the mismatch. Establish one Review Brief containing the Epic identity and criteria; authority; base and candidate commits; ordered remediation commits when present; included and excluded paths and artifacts; verification provenance; goal revision; ordinal; assessment kind; mode; and approved scope. Dispatch exactly one route: Mulgae through an executing agent that has loaded and follows the installed same-release `$use-mulgae`, Herdr through `$aquarium:herdr-review` on an exact supported committed target with an explicit reviewer, Independent Review through `$aquarium:independent-review` with three fresh static report-only host subagents, or waiver through the coordinator's assessment of the same brief. A waiver launches no reviewer and never removes the direct audit or required verification.

For each completed delegated review or waiver assessment, record the next positive ordinal, assessment kind, route, operation, evidence reference, optional backend check, provenance, finding IDs, reported severity, effective priority, validity, and disposition. Ordinals one through three use `assessment-kind=work-unit` and `review-mode=remediation-eligible`; ordinal four and every user-authorized later review use `assessment-kind=remediation-confirmation` and `review-mode=confirmation-only`. Incomplete or failed operations consume no ordinal; native recovery reuses the pending ordinal. Switching after completion uses the next ordinal, while switching after incomplete work retains it. On resumption, reconstruct the ordinal and assessment kind from verbose Validation Procedure history and exact route evidence; verify original-root lineage only for Mulgae. Cold validation never selects `hardening-deferral-eligible` mode.

## Audit the Epic Directly

Run the audit without source mutation. An existing authorized Codex goal may remain active during the audit:

1. Build a requirement-to-owner-to-production-to-test-to-document matrix across every member task. Trace runtime wiring, consumers, persistence, concurrency, migrations, generated artifacts, failure and recovery behavior, operational guidance, external dependencies, roadmap consistency, repository-defined dossier disposition when applicable, and coverage by the completed epic's canonical sources.
2. Before Judge dispatch, the Primary or an authorized Worker runs only repository-authorized checks needed for the Epic claim and supplies actual results. The report-only Judge inspects current code, original requirements and supplied evidence directly without running checks. The Primary records the aggregate audit and check result. Keep current agent-run, explicit user-run, unavailable, forbidden, stale, external, live, commit, and upstream publication evidence distinct; narrow green checks do not prove uncovered requirements.
3. Complete the direct audit and adjudicate its findings first. Route an owned blocker through authorized remediation and a fresh audit before the first provider review; clean or Low-only audit evidence proceeds to the independently required review. Run the selected route on one exact latest committed Epic target that excludes unrelated work. Supply the exact Epic objective and criteria, base and candidate commits, ordered Epic or remediation commits, changed paths and artifacts, excluded state, and verification evidence. Herdr may use `HEAD`, commit, or range; Independent Review receives one exact bounded static target; waiver performs the coordinator assessment without launching a reviewer.
4. Admit only a valid route-specific completed evidence combination. Mulgae requires its exact live-source root, or verified historical composite plus coverage, committed publication, successful findings query, and backend `pass` or `fail`; Herdr and Independent Review require reviewer provenance with backend `not-provided`; waiver requires `review-operation=waived`, coordinator provenance, `review waived`, and the assurance limit. A completed checkpoint consumes its ordinal independently of backend result, finding adjudication, and semantic completion. Zero findings, reviewer success, or process exit alone is insufficient.
   Record and route the final review operation, finding confirmation, completion state, required evidence, applicable blockers, and Low settlement through separate serial Procedure decisions. Do not compress these prerequisites into a combined final-review guard or let a later clean count bypass an earlier incomplete gate.
   Record `structured_extraction_status` independently as `structured`, `mixed`, or `reports_only`. `reports_only` is not itself a failure and does not replace or relax any completion condition above; the accepted reports remain authoritative, and every extracted finding remains an advisory hypothesis that requires local verification.
5. Verify every candidate finding against current authority and implementation. Record only confirmed gaps; do not turn review hypotheses into work automatically.

With Podway active, create or resume the matching prepared validation session only after approval, re-observe and `begin` it, then run `podway observe --json` before each bounded audit or remediation delegation and verify the expected Procedure ID, epic and baseline identity, session, lifecycle, revision, attempt, goal revision, and current node. Record `workflow-owner=epic-validator` at `capture-baseline`. Independently verify returned native evidence before recording the baseline and fresh audit or deciding whether gaps exist. At final outcome acceptance, record `acceptance-source=user`, the actual user decision in `acceptance-authority`, and the exact `accepted-target`; leave acceptance unset until the user answers. The continuing Epic handler's `delegated` validation-closeout route does not apply to this independent workflow.

Select only actions allowed by `guidance.allowed_actions` and represented by current `mutation_templates` entries. Record total confirmed count only as descriptive evidence. Separately record the operational result, confirmation-needed count, current blocker count, eligible Low count, and blocking-rework authority. Clean and Low-only audit states advance toward the independently required final review; only an adjudicated blocker with the current original remediation envelope advances to remediation. Do not record candidate findings as confirmed Podway gaps before adjudication.

## Group and Complete Remediation

Group confirmed gaps by canonical requirement owner and coherent implementation boundary. Do not add new roadmap tasks or invent task IDs.

- For a gap owned by one existing task, group the remediation under that task ID and hand the isolated correction to `$aquarium:task-commit` under that task ID. If the roadmap defines a reopen state, transition through it and return to success; otherwise preserve the successful state without adding remediation history to the roadmap.
- For a cross-task seam or omitted epic-level design requirement owned by no existing task, group the remediation under the epic ID and hand the isolated correction to `$aquarium:task-commit` under that epic ID.
- For work owned by another repository, stop with its owner, exact revision, and missing evidence. Never mutate that repository.

If ownership is ambiguous, stop before remediation and report the missing authority. Order task-owned groups by dependencies and roadmap order, then epic-owned groups. Never run two remediation groups concurrently.

For each remediation group:

1. Implement the smallest complete correction, add or update regression coverage and any durable specification required by changed current behavior, and run affected authorized checks. In an enrolled repository, include one concise release-note `entry` for a changed shipped outcome or record `intentional no-note`; otherwise record `not-enrolled`.
2. Fix every valid in-scope Medium-or-higher finding from the current admitted audit or completed review, then repeat affected checks without starting a per-group or follow-up review. Apply each Low disposition under the shared contract with its required local checks.
3. Update the roadmap only for an actual lifecycle change or actionable downstream handoff. Record Low future work in the canonical deferred-feedback or TODO owner, not as accepted risk. Never add a routine `Validation remediation`, `Validation record`, command log, tested snapshot, runtime path, run ID, or commit list.
4. Record resulting remediation commit IDs in Podway and the orchestration report, not in canonical documentation.

Confirm the group's diff, including lifecycle, record, and current-semantics documentation decisions, equals the verified correction for the recorded source findings. Record acceptance of that exact candidate by the user or under their current delegation. The approved validation envelope supplies one-commit authority for each actual owned remediation group; if it does not cover the proposed effect, obtain separate authority. Never inherit this authority from a normal Epic member-Task completion grant.

Hand that exact scope, its evidence, active validation session, owning task or epic ID, lifecycle and record edits or their explicit absence, release-note target and decision, source `review-route`, `review-operation`, `review-evidence-reference`, `backend-check-result`, `assessment-provenance`, consumed `assessment-ordinal` and `assessment-kind` or their explicit inapplicability, waiver summary or explicit inapplicability, complete local-settlement composition or its explicit inapplicability, zero or more approved promoted manifest path and digest pairs or their explicit absence, exact candidate acceptance, and approved one-commit authority to `$aquarium:task-commit`. Before the first delegated review, provide the exact direct-audit evidence and mark source review fields inapplicable. For this remediation-group commit, state that whole-Epic confirmation of corrected bytes is still pending; do not present the source assessment as coverage of the correction or ask for another commit approval when the complete handoff already carries it.

Verify the returned commit snapshot, residue, and hook evidence before completing the remediation group. Complete an authorized Codex goal only when its full objective is achieved; a remediation commit alone does not establish that. The later whole-epic confirmation owns provider coverage of this remediation-group commit. Accepted local settlement is not a remediation-group commit: carry its delta into the final epic-ID closeout candidate, preserving the source review's coverage limit, exact target and current local proof.

## Converge and stop on repeated findings

After nonlocal blocking remediation from the first completed work-unit assessment, discard stale matrix, checks, and result evidence while preserving the exact trigger set and earlier route lineage. Continue any authorized Codex goal while refreshing the direct audit and running one ordinal-two `work-unit` assessment through the current route from the latest committed snapshot; an explicit safe route change remains available. A Low-only initial result does not require this cycle.

When ordinal two establishes a finding or completion gap requiring another provider assessment, remediate that verified set, rerun affected checks, refresh the complete Epic audit, and run one ordinal-three `work-unit` assessment from the latest committed snapshot. Stop early when ordinal two or three is clean or reaches completed local settlement.

If round three is incomplete, follow supported exact recovery within the approved envelope; otherwise stop without resubmitting the review. When it establishes a finding or completion gap requiring another provider assessment, freeze that correction set, implement the authorized correction, rerun affected checks, and perform one ordinal-four `remediation-confirmation`. Restrict its direct re-audit and Review Brief to the prior finding IDs, correction commits, invalidated criteria, directly affected callers, contracts and tests, and correction-caused regressions. Carry unaffected criterion assessments only when current evidence proves they remain valid. A material objective, requirement, or changed-surface expansion stops for an explicitly approved new goal revision.

Continue when route-specific readiness and workflow verification pass and no valid finding remains. For Mulgae, a failed CI decision remains a verification gap even without findings; Herdr, Independent Review, and waiver instead require `backend-check-result=not-provided` and never invent CI evidence. After ordinal four, a valid finding requiring further provider assessment blocks validation and stops for one correction-and-confirmation budget or `stop`; risk acceptance and deferral are unavailable. When only eligible local corrections or Low findings remain, settle the complete current set inside the approved envelope. Mixed nonlocal sets retain their full ordinary rework and confirmation scope. Self-evident fixes receive integrity checks, bounded behavioral fixes receive a focused test, future risks go to the canonical deferred-feedback owner, and structural work becomes a TODO candidate. State that the review predates changed bytes.

Resolve every `Needs confirmation` finding before selecting the final-review decision. Use existing read-only evidence first. If resolution requires a check, run it only when the approved validation envelope already authorizes it; otherwise leave the decision unset and ask for bounded confirmation authority. Reclassify the same finding as `Valid` or `Invalid`, manually rework `final-review`, and evaluate the decision again. Do not consume another review ordinal unless the selected review runs again.

Each user-authorized nonlocal correction after ordinal four grants one remediation and one next-ordinal remediation confirmation only. Apply local eligibility again after that review. Ask again only when a remaining finding or completion gap requires another provider assessment without remaining authority.

With Podway active, record each remediation group, fresh audit, reported severity, effective priority, finding ID, and completed disposition. Preserve applicable audit and provider obligations under separate namespaces at final review; provider counts do not erase an audit Low basis. When Medium-or-higher work exceeds the current envelope, select its supported `user-direction` route, record `direction-classification=user-direction` and the exact issue set at `await-user-direction`, complete that action, and stop at `choose-user-direction` with the decision unset until the user answers. Reaching or completing the recording action grants no source change or provider call. Assess criteria and complete the session only from the latest evidence plus the completed Low disposition record.

When an external blocker is resolved, revalidate its exact committed revision and evidence before restarting the audit. Product or canonical-document changes make affected evidence stale. A completed Low disposition may use its required local checks without provider re-review, but the preceding review must be recorded as predating those bytes. An approved promoted-evidence projection remains outside the review target and receives commit-boundary validation.

Establish readiness for final closeout only when every required check has current passing evidence, the whole-Epic selected-route operation and evidence combination are complete, any Mulgae backend check passes, every actual requirement has a conservative completion assessment with zero `unmet` and zero `unverified` criteria, every member task has a roadmap-defined successful state, no epic-owned residue remains, and one of these closeout conditions holds:

- The fresh Codex audit and latest review are clean.
- No unresolved valid or confirmation-needed finding remains, and the frozen eligible local correction and Low sets have zero pending local corrections and Low dispositions, zero current blockers, and a passing `aquarium-low-disposition-verification` result on the exact final target. Each local correction has a completed `local-verified-fix` record; each Low finding has a completed `low-self-evident-fix`, `low-bounded-fix`, `low-deferred-feedback`, or `low-todo-candidate` disposition. The source Low count may remain nonzero.

For an active or in-review Epic reaching successful closeout, classify the remaining execution-SOT content and promote durable requirements, decisions, and operating guidance to their canonical owners. Inventory every canonical roadmap consumer of its dossier. Update only this Epic's link, retain a shared dossier while another consumer is non-terminal or still references it, and delete it only as the approved last-consumer disposition. Stop on unowned durable content. A completed-Epic audit does not recreate a deleted dossier.

An incomplete review or `stop` disposition never supports completion. Store the final audited snapshot, commands, runtime paths, run identities, and detailed evidence only in Podway, native runtime, and the orchestration report. Prepare an isolated epic-ID diff only when lifecycle, dossier settlement, a completed local correction, Low disposition or future-work owner, or an actionable handoff changed; otherwise record an explicit no-change result. After assessing the goal, record its outcome and obtain user acceptance at `approve-closeout` for the exact candidate, lifecycle and record decisions, release-note decision, dossier disposition, and evidence. Only then hand any required commit to `$aquarium:task-commit` under its existing one-commit authority. Record verified commit and residue results at `closeout`; never create a validation-record or empty commit.

With Podway active, follow [Finalize Before Reporting Completion](../../references/podway-integration.md#finalize-before-reporting-completion) after verifying the required canonical commit or approved no-change result and clean residue. Complete the terminal Action and verify the shared finalization postconditions before declaring validator completion. Record and verify `handed_off` with the exact final validation-owned repository result when one is required. When no final repository result is required, record `not_required` with the verified reason even if earlier task or remediation commits exist. Leave the final terminal session intact and never invent a reference or choose force cleanup.

Declare validator completion only after the closeout readiness above, actual user acceptance, and the verified required commit or explicit no-change result with no validation-owned residue. Verify that every member task and the Epic have roadmap-defined successful states. With Podway active, finalization must also be verified.

## Hand Off Commits and Report Safely

Every actual remediation, lifecycle, or actionable-handoff commit goes through `$aquarium:task-commit`. Include repository, roadmap, task or epic ID, lifecycle and record decisions, release-note decision, isolated scope, verification evidence, `review-route`, `review-operation`, `review-evidence-reference`, `backend-check-result`, `assessment-provenance`, the consumed `assessment-ordinal` and `assessment-kind` or their explicit inapplicability, the waiver summary or explicit inapplicability, the complete local-settlement composition defined by the shared finding-disposition contract or its explicit inapplicability, zero or more promoted manifest path and digest pairs or their explicit absence, and one-commit authority.

On the Podway path, include the current session's continuation from the [commit handoff requirements](../task-commit/SKILL.md#reconcile-roadmap-context).

That skill owns staging, Lore and Sanho commit-boundary checks, the direct commit, hook reconciliation, and byte-for-byte snapshot verification. Never commit independently.

Use `$use-sanho` directly only for separately authorized synchronization outside the commit boundary. Commit is not upstream publication. Do not push, amend, open or modify a PR, release, or claim live validation without separate authority and evidence. Request renewed approval before further mutation when the resolved execution SOT source set or its requirements change materially, or when remediation would add a new requirement, cross repository scope, cause destructive impact, or exceed a safely isolatable existing epic requirement. Renew the dossier waiver for an active or in-review epic when the revised source set still has no dossier.

Do not create or read `.aquarium` or other shadow state. Resume from roadmap, Git history and worktree, current goal, recoverable approval, repository evidence, and the selected route's exact records. Preserve the same validation session, review lineage, frozen Low set, completed dispositions, pending count, and consumed one-pass authority. Never restart the audit, replace a review root, or reset a budget merely to rebuild conversational context. At each stop report baseline, audit status, remediation groups and owners, current goal, commits, checks, selected route, operation, evidence reference, provenance, backend-check result, route-specific findings status, canonical changes or explicit no-change state, worktree boundaries, publication state, and exact next safe action. On the Podway path, include the shared finalization report fields and distinguish repository completion from pending session finalization. For a waiver, also report `review waived`, its authority and reason, and the resulting assurance limitation; never present it as delegated review.

Retain `workflow-owner: aquarium:epic-validator` and the exact candidate binding in every commit handoff under the shared attribution contract, including owned corrections and closeout.
