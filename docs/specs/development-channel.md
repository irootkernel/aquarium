# Development Channel Specification

The explicit-only `$aquarium:aquarium-dev` workflow manages one canonical local-`main` checkout per supported project on Darwin arm64. Supported producers are Aquarium, Podway, Mulgae, Gaori, Sanho, and Dolgorae. Dolgorae remains unenrolled until its repository commits and registers an approved producer generation; production review paths continue to use only the verified globally installed release binary.

Diagnosis is read-only. Enrollment metadata, a native hook marker, an initial or recovery build, and installation of the user-local launcher are separate effects with separate approvals. All Aquarium-owned development state lives below `~/.aquarium-dev/`; `~/.aquarium/` is reserved for production use.

Every producer owns `make aquarium-dev-describe` and `make aquarium-dev-build AQUARIUM_DEV_OUTPUT=<absolute-empty-directory>`. A build admits only a clean checkout whose `HEAD` is local `main`, consumes committed bytes, emits one exact-SHA manifest, and writes only into the supplied staging directory. Aquarium's producer packages one Codex plugin artifact from the committed Root Kernel marketplace and Aquarium plugin, including its bundled skills, and gives the derived plugin version the exact `-dev.<sha12>` identity. Podway, Mulgae, Gaori, Sanho, and Dolgorae each produce one executable at exactly `bin/<project-id>`.

The manager validates the declared identity, version, path containment, and canonical checksum before immutable promotion. A stable executable entry resolves through the single atomically advanced `current/<project-id>` selector. A failed build preserves the prior selected generation. Every executable consumer holds a shared lease on its immutable generation for its process lifetime, so cleanup requires the exclusive form of that lock. Plugin generations remain retained until a lease-aware plugin consumer owns their complete use lifetime.

The separately approved `~/.local/bin/aquarium-dev` launcher prefers a supported tool's exact `~/.aquarium-dev/bin` generation and otherwise resolves only that tool from the caller's original global `PATH`, excluding both Aquarium state roots. If both generations are absent for required Podway, Mulgae, Gaori, or Dolgorae, the command fails closed and requests `$aquarium:dev-setup`; Sanho is explicitly optional. An invalid selected development generation also fails closed without fallback. Unknown commands remain rejected. The child receives `~/.aquarium-dev/bin` first in `PATH`, while the caller's environment and any existing `CODEX_HOME` remain unchanged. The launcher does not create a Codex home, perform authentication, install a plugin, or configure MCP servers.

Host-local development evidence is neither stable installation nor release or distribution proof. Exact executable behavior is owned by the [`aquarium-dev` skill](../../plugins/aquarium/skills/aquarium-dev/SKILL.md), its [development contract](../../plugins/aquarium/skills/aquarium-dev/references/development-contract.md), the [manager](../../plugins/aquarium/skills/aquarium-dev/scripts/dev_manager.py), the [launcher](../../plugins/aquarium/skills/aquarium-dev/scripts/aquarium_dev_launcher.py), the [Aquarium producer](../../plugins/aquarium/skills/aquarium-dev/scripts/build_aquarium_artifact.py), and the repository [Makefile](../../Makefile).
