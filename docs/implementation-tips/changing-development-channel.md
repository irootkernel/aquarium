# Changing the Development Channel

Read the [development contract](../../plugins/aquarium/references/development-contract.md) before changing the manager or a producer. Keep repository production behind the two common Make targets; the manager must not infer project-specific build commands or artifact layouts.

Producer changes need focused tests for clean local-main admission, committed-byte provenance, exact SHA and development-version identity, output containment, and checksum validation. Managed-service producers additionally own one immutable development-safe command and controller bundle, strict status/plan/apply results, busy deferral, and recovery behavior; Aquarium must not learn their internal daemon topology. Manager changes need failure-path coverage for approvals, enrollment ownership, atomic current or pending publication, exact-token service activation, selector replacement, cleanup, and diagnostics. Launcher changes must prove that `~/.aquarium-dev/bin` alone is prepended, the caller's remaining environment including `CODEX_HOME` is preserved, foreground fallback remains bounded, and unavailable managed services never fall back to production.

Preserve the distinction between local development evidence and stable release evidence. An external producer handoff should identify its exact clean local-main commit and include both target outputs, checksum proof, embedded runtime identity diagnostics, and focused tests. Aquarium can consume that handoff but does not own or implement the external repository's build or release behavior.

The CLI and MCP server share the same operation dispatcher. Keep approval validation in the core and verify actual stdio initialization, tool discovery, and result/error parity. Runtime tests must cover explicit installation, failed-update preservation, plugin/runtime identity mismatch, stable hook migration, and continued access to previous runtime generations. Never download dependencies inside the automated test suite; its SDK comes from the pinned test environment.
