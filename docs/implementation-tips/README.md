# Implementation Tips

This index links non-normative guidance for changing, verifying, and releasing Aquarium. Exact repository instructions and executable authorities win if guidance conflicts.

## Guides

- [Changing skills](changing-skills.md) covers entrypoint ownership, shared references, approvals, and cross-skill handoffs.
- [Changing Procedures](changing-procedures.md) covers graph ownership, versioning, installation bytes, and Podway compatibility.
- [Changing inspectors](changing-inspectors.md) covers conservative local inspection, schemas, safety, and fixtures.
- [Testing and releasing](testing-and-releasing.md) maps change classes to focused checks and exact-candidate release proof.

## Starting Point

Follow [`AGENTS.md`](../../AGENTS.md) for repository behavior, ownership, approval, commit, and release rules. Read the owning skill and every directly linked reference before modifying a workflow. Use [`TESTING.md`](../../TESTING.md) to select the narrowest authoritative test stage and understand its evidence boundary.

These guides explain established patterns. They do not authorize a mutation, commit, network action, provider call, release, or publication.
