# Qualifying Herdr review

Use this guide when qualifying a changed Herdr review or migration contract.
The [supervision contract](../../plugins/aquarium/references/herdr-supervision.md)
owns review admission, and the [migration runbook](../ops/herdr-migration.md)
owns diagnosis of legacy state and separately approved updates. This guide grants
no provider, host, session, installation or publication effects.

## Bind the candidate and environment

Record the canonical checkout, base and candidate Git identities, included
index or committed bytes, excluded worktree state, upstream skill identity and
native CLI/server identities. A CLI version, canonical skill file or successful
structural check establishes only that dimension. Observe actual host discovery
and reviewer readiness separately in the intended local Herdr session. Missing
caller context stops Herdr inspection and control; it does not block peer routes.

Use the original requirement owner for each scenario. Preserve completed Task
and review evidence, consumed ordinals and correction authority after context
restoration. Do not obtain a new budget by creating another session. Keep
performed and unperformed outcomes in native workflow evidence; promote only
bounded eligible artifacts under the evidence-residency contract.

## Required observed scenarios

| Surface | Required observation |
| --- | --- |
| Targets and purposes | Both requested Codex and Claude reviewer kinds cover `staged`, `head`, `commit` and `range`, change findings and criterion-level completion. Read index or resolved Git objects; exclude unrelated worktree bytes. Unsupported, conflicted and empty staged targets stop before dispatch. |
| Readiness and startup | Missing CLI, upstream skill, reviewer or actual caller context blocks only Herdr. Native-reported client/server incompatibility preserves the host; version differences follow Herdr's current compatibility contract. Startup approval or question UI waits for the user's decision without an upgrade, replacement or fallback. |
| Completion and output | Correlate the actual fresh reviewer with submission and observed activity. Read the complete purpose-specific result; settled or unknown state alone cannot pass. Exercise expanded native reads and the Markdown file fallback from the same reviewer when needed. |
| Failure and recovery | Timeout, stalled submission, blocked UI, replacement identity, missing output and lost observation preserve the exact operation and available evidence. Reject duplicate prompts and false completion. A failed or incomplete operation consumes no assessment ordinal. |
| Embedded workflows | Task, Epic and validation preserve route selection, complete staged preparation, assessment kind and ordinal, finding lineage, correction authority, closeout acceptance and commit handoff, including after context restoration. |
| Legacy migration | Prior canonical and custom sources, completed Orca evidence, incomplete checkpoints, active or unknown workers and old snapshots follow the documented preservation or refusal path. Verify terminal settlement before another review and eligible archival before a successor. |
| Peer routes | Mulgae, Subagent Review and waiver keep their native prerequisites, evidence, recovery, verification and acceptance contracts. No Herdr readiness requirement reaches them. |

Every required observation needs its actual outcome for the exact candidate.
Fixture receipts prove only the recording and graph behavior they execute.
Static contract review cannot substitute for a live reviewer, and the
implementer's report cannot substitute for Master's required manual outcomes.
Leave missing, conflicting or unreadable evidence unverified.

## Checks and handoff

Run focused helper regressions and the applicable local Make gate under
[`TESTING.md`](../../TESTING.md). Native Podway scenarios separately qualify the
changed declarations, guards, recording and graph transitions; they do not run
review providers or establish semantic agent behavior. An installed development
binary is development-contract evidence. The official archive/checksum gate
remains a release-preparation obligation.

After qualification, hand the exact candidate, native evidence, criterion
assessment, findings and explicit remaining gaps to the owning workflow's
selected review route. A qualification scenario does not change that route.
Keep member acceptance, Master's overall Epic acceptance, installation and
publication separate.
