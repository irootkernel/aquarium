# Privacy

Aquarium contains instructions for Codex. The plugin does not operate a hosted service or collect telemetry itself.

Some instructed workflows can invoke local or third-party tools after explicit user approval. Bounded read-only network operations may be authorized by an explicit tool selection or skill invocation without a second network prompt.

`dev-setup-bundle` reads only the explicitly supplied local YAML manifest and the listed Git repositories needed for setup preflight. It keeps the manifest path and digest only for the active request, does not discover sibling repositories, persist the manifest, or transmit its contents, delegates the selected global union once to `dev-setup-global`, and delegates repository state to `dev-setup`.

Explicitly invoking `aquarium-dev` reads only the named Git checkout and Aquarium-owned host-local state needed to diagnose the development channel. Separately approved enrollment, hook, build, managed-service activation, and launcher-installation operations may write exact committed artifacts and bounded metadata below `~/.aquarium-dev/`, the exact Aquarium-owned marker in the named checkout's native hook, and the user-local `~/.local/bin/aquarium-dev` launcher. Separately approved runtime installation or update contacts `pypi.org` and `files.pythonhosted.org` to download hash-verified binary wheels into a private virtual environment below `~/.aquarium-dev/manager/`; it uploads no repository source. For a managed service, Aquarium invokes only the immutable producer-owned controller with its project runtime root and exact target generation; that controller owns any LaunchAgent, daemon, socket, registry, log, or recovery access and returns bounded status, plan, and result metadata. The launcher inherits the caller's environment and prepends only `~/.aquarium-dev/bin`; it neither copies credentials nor creates or changes Codex authentication, plugin, or global MCP configuration. Aquarium ships its bundled MCP registration in the plugin itself. Development artifacts and diagnostics are local integration evidence and are not uploaded or promoted to release evidence by this workflow.

Explicitly invoking `dev-setup-global` without a component list automatically contacts the documented official metadata and raw-file endpoints for every supported global component. A scoped continuation contacts only sources for its named components. Dolgorae uses official GitHub Releases metadata; Sanho, Mulgae, Gaori, Sorage, and Podway also download their documented public paired-skill files to ephemeral storage for comparison with `~/.agents/skills/use-*`. These reads send no repository or local skill content, persist no downloaded file without separate approval, and authorize no installation, mutation, provider request, or other network endpoint. `dev-setup` performs no upstream freshness lookup and does not read canonical global skill contents.

Explicitly invoking `release-qa` automatically queries the repository's configured Git remote and hosting Release metadata to establish remote `main`, tags, and the latest stable published release. Configured Git and hosting clients may use existing ambient authentication for private repositories, but the skill does not inspect, read, copy, print, persist, refresh, or reconfigure credential material, initiate authentication, upload source, or authorize network access from QA scenarios; unavailable access leaves the QA result incomplete.

Explicitly invoking `release-handler` performs the same bounded read-only release discovery and may delegate one exact candidate to `release-qa`. It reads repository instructions and release policy, version authority, the declared repository-local release notes, material release-delta source and documentation surfaces, and local, remote, tag, and hosted Release metadata needed to reconcile that candidate and any matching partial publication. It creates no tracked or temporary resume manifest. Commits, pushes, tags, hosted Release creation, destructive replacement of published objects, and the separate post-release next-cycle commit remain separately approved actions; the workflow never treats ambient authentication as publication authority.

Release QA stores bounded cluster reports, controlled-environment records, captured command output, and scenario material under private `/tmp/release-qa.*` evidence roots. The same roots hold the machine-readable frozen record, confirmation manifest, attempt claim, settlement admission, and terminal result. These files contain bounded identities, Git objects, procedures, outcomes, mappings, digests, and local evidence paths, but must exclude credentials, raw source contents, and unrelated source. Aquarium reports each retained path for inspection but does not delete it on ordinary completion. The user decides when to remove the files.

Explicitly invoking `independent-review` performs local repository and Dolgorae discovery and one bounded official release-metadata lookup. It freezes that verified metadata for the invocation and repeats only local candidate checks before source-bearing operations. Invoking `orca-review` by name or through an explicit request naming the review target and reviewer performs local repository and Orca discovery and may start the installed local Orca runtime; it does not discover or use Dolgorae. Aquarium binds every review to one declared source scope and applicable Git identity. Reviewers run as same-user processes, so scope rules are authorization and instruction boundaries rather than an operating-system read sandbox. Independent Review sends the captured scope to one fresh Codex Reviewer through the verified supported Dolgorae runtime and creates no Orca object. Orca Review starts the reviewer named in the request through Orca in the current registered worktree. A staged Orca review reads the live `git diff --cached` target directly and relies on explicit read-only prompt restrictions rather than a capture or repository-state fingerprint. Reviewers are prohibited from writing in the registered worktree. All Orca reviewers may create or update review-related temporary files, native session state, tool output, and reports outside the registered worktree, including under `/tmp`, `/private/tmp`, `$TMPDIR`, or provider-owned directories. External review files alone do not cause a warning or failed review. Reviewers return the paths of retained report files used to deliver the result; routine temporary files need no inventory. Aquarium does not automatically remove reviewer-owned files. An explicit request naming the target and reviewer authorizes only that bounded static review transmission and external review output; it authorizes no tests, builds, authentication, installation, update, retry, reviewer switch, source edit, commit, push, or publication.

Explicitly invoking `test-setup` reads the selected local repository's test authorities and may run its bundled inspection script without executing project code. Applying an approved test-setup diff does not authorize tests that create containers, databases, external sandbox resources, paid requests, or other network or persistent effects; the skill discloses those effects and obtains separate approval before execution. It never opens known credential stores or credential-named paths, never emits raw authority contents or credential values in its report, and refuses an E2E target that cannot be verified as non-production. Inline values in ordinary source, test, manifest, or Make files may be read as part of structural inspection but are not reported verbatim.

Explicitly invoking `docs-setup` reads regular non-symlink tracked text plus non-ignored untracked text below discovered canonical documentation owners, as needed to inventory roles, roadmaps, identifiers, and references and verify an approved documentation diff before staging. It may run its bundled local inspector without executing project code or contacting a network. It excludes `.env*`, credential, authentication, key, secret, token, binary, oversized, ignored, and symlinked paths; reports category counts for all exclusions and paths only when a canonical authority or symlink exclusion makes the result unverifiable; and emits paths, line numbers, identifiers, allowlisted statuses, and structural findings rather than document contents. Applying an approved documentation diff does not authorize staging, commits, synchronization, publication, or project commands.

- Aquarium's trusted local commit hook receives the proposed shell command and working directory from Codex, resolves the local Git root, reads the effective Git configuration scope and value for `user.name` and `user.email`, lists tracked paths, and reads up to two million characters from tracked roadmap candidates to detect lifecycle states. It writes no project state, stores no telemetry, and transmits none of that command, path, identity, repository, or roadmap content over the network.
- Sanho can contact a configured documentation Git remote. Its selected-skill freshness comparison contacts GitHub automatically, and an approved `use-sanho` installation writes the verified four-file payload to a user-scoped Codex skill directory.
- Mulgae can transmit an explicitly preflighted review target to providers configured by the user and retains complete provider stdout and stderr in private local runtime artifacts. A selected Codex credential profile projects only its `auth.json` into a disposable local runtime; profile homes and credentials remain machine-local and must not be reported or committed. Its `dev-setup-global` freshness comparison contacts GitHub automatically, an approved `use-mulgae` installation writes four files below `~/.agents/skills/use-mulgae`, and an optional attached STDIO MCP process remains bound to the selected local repository. Neither setup skill runs reviews, starts the MCP server, captures a review target, invokes a provider, authenticates Codex, or transmits source.
- Dolgorae retains immutable captures, checked review lifecycle state, settlement evidence, and private credential carriers in its user-owned `~/.dolgorae` runtime. Aquarium does not migrate or fall back to the v0.1.0 Application Support location. Independent Review uses Dolgorae directly to send the disclosed capture to one fresh Codex Reviewer and creates no Orca objects. Orca Review uses Orca alone to start the reviewer named in the request under the user's existing provider account and applicable data-handling policy. Aquarium reports bounded evidence and does not expose credentials, raw transcripts, provider payloads, or reviewer reasoning.
- Lora installation contacts npm and GitHub and writes selected skills to the Codex user-global skill directory.
- Cursor Team Kit Deslop installation contacts GitHub and npm after separate approvals, resolves an exact upstream commit into ephemeral storage, and writes the upstream `SKILL.md` and MIT LICENSE to `~/.agents/skills/deslop`. Aquarium does not retain that source in its plugin distribution.
- Humanizer installation contacts GitHub after separate lookup and installation approvals, resolves the supported `v2.11.1` release in ephemeral storage, and writes its verified `SKILL.md` and LICENSE to `~/.agents/skills/humanizer`.
- im-not-ai installation contacts GitHub after separate lookup and installation approvals, materializes the exact supported `v2.3.2` Codex copy under an isolated temporary `CODEX_HOME`, and writes the verified payload plus LICENSE to the active Codex skill root. Setup does not invoke either writing skill or send prose to a provider. A later approved Korean documentation pass may create local `_workspace/` output; repository guidance requires that output to stay untracked and be removed after the accepted text is applied.
- Gaori stores local test logs and summaries under `.gaori/`; raw logs are intentionally unredacted and can contain sensitive process output. Its selected-skill freshness comparison contacts GitHub automatically. Approved installations write four files to `~/.agents/skills/use-gaori` and one file to the independent `~/.agents/skills/use-gaori-status` skill. An optional attached STDIO MCP process remains bound to the selected local repository.
- Sorage stores its configuration, database, token, logs, and default managed Vault under `~/.sorage`, or the user-selected `SORAGE_HOME`, and may create a derived `.sorage/INBOX.md` marker in registered Project bindings. `dev-setup-global` checks its version and paired skill without repository resolution; `dev-setup` owns Project binding and ignore readiness. Native doctor and Project resolution make no network request but may apply database migrations or update journal state, so neither runs in Plan Mode and the side effect is disclosed before execution. Initialization, Project registration, skill installation, and ignore changes require separate approval. Aquarium setup never reads Handoff content, starts the daemon, enables backup or remote push, or edits the Vault. The global freshness comparison contacts GitHub automatically, and an approved `use-sorage` installation writes one file below `~/.agents/skills/use-sorage`.
- Podway stores workspace configuration and local task history under `.podway/` and operates a same-user local daemon. It does not transmit source or evidence over the network; its selected-skill freshness comparison contacts GitHub automatically, and an approved `use-podway` installation writes four files below `~/.agents/skills/use-podway`.
- An explicitly approved `task-handler` or `epic-handler` plan handoff writes the approved Markdown plan once to `.podway/runtime/handoffs/<initial-session-id>/plan.md` with private local permissions. Aquarium does not create this file for ordinary execution or plan-only requests, transmit it, stage it, or commit it; Podway records only its local path, SHA-256, byte size, and media type. The owning handler retains it while the workflow may resume and removes only that exact temporary file after successful final closeout.
- Ouroboros may transmit only the source and document scope displayed in an explicitly approved Aquarium execution envelope when a selected upstream provider-backed operation requires it. The selected `ooo --version`, `ooo codex doctor`, `ooo mcp doctor --json`, and `codex mcp get ouroboros --json` diagnosis probes are local and read-only: they do not contact a provider, initiate authentication, or make a network request, though MCP diagnosis may inspect bounded local authentication-readiness metadata without exposing credential material. Aquarium setup never calls a provider, authenticates, transmits repository source, or starts an execution loop. Ouroboros freshness diagnosis separately contacts official PyPI metadata when selected and disclosed. Artifact comparison invokes the selected package's native asset resolver in an isolated Python subprocess and reads each discovered Codex home and legacy Ouroboros copies in `~/.agents/skills`, without reading credentials. Approved `uv` package installation, `ooo codex refresh`, `ooo setup --runtime codex --non-interactive --mcp-mode auto`, explicit supported MCP replacement, and legacy shared-skill migration are persistent actions; one exact approval may cover the listed actions and homes. They may contact their documented package or runtime endpoints.

Those tools and services have their own data handling policies. The skills instruct Codex not to open known credential stores or credential-named paths and not to print, copy, or persist credential values. Structural inspection may incidentally read inline values in ordinary source, test, manifest, or Make files as disclosed above, but setup does not transmit repository source. Users should inspect proposed commands, capture sets, exclusions, and provider routing before approval.

Project configuration and ordinary runtime evidence remain in the locations owned by each tool. Ignored Mulgae, Gaori, and Podway runtime paths, derived Sorage paths, and their identities are not durable repository authority and must not be copied into tracked documentation as execution logs. When an approved workflow has a concrete downstream need that code, tests, specifications, and Git history cannot satisfy, it may copy only reviewed bounded non-sensitive structured evidence into a tracked `aquarium.promoted-evidence/v1` package under `evidence/aquarium/` or one custom repository-relative tracked root named in the applicable repository `AGENTS.md` Project Configuration. Standard promotion excludes raw logs, excerpts, accepted reports, provider transcripts or prose, quotes, diagnostics, export bundles, credentials and credential paths, runtime or provider identities, timestamps, usernames, native-home or absolute paths, machine-specific paths, and Podway databases or history. This package is evidence, not central project state.

Aquarium does not bundle Sorage, Lora, Ouroboros, Cursor Team Kit, Humanizer, or im-not-ai skill or documentation sources. Approved installations obtain those sources directly from their official upstream repositories or packages and store them only in the owning user-scoped tool locations.

Aquarium procedures instruct agents to record bounded summaries, provider operation identifiers, revisions, exit statuses, paths, and digests in Podway rather than source contents, credentials, raw provider prompts or payloads, transcripts, generated documents, or full logs. Podway actor labels are correlation metadata, not authentication.
