# Privacy

Aquarium contains instructions for Codex. The plugin does not operate a hosted service or collect telemetry itself.

Some instructed workflows can invoke local or third-party tools after explicit user approval. Bounded read-only network operations may be authorized by an explicit tool selection or skill invocation without a second network prompt.

`dev-setup-bundle` reads only the explicitly supplied local YAML manifest and the listed Git repositories needed for setup preflight. It keeps the manifest path and digest only for the active request, does not discover sibling repositories, persist the manifest, or transmit its contents, and delegates every selected tool action to the same disclosure and approval boundaries as `dev-setup`.

Selecting Sanho, Mulgae, Gaori, or Podway in `dev-setup` automatically contacts that tool's official GitHub Releases metadata endpoint and `raw.githubusercontent.com`, downloads four public skill files to ephemeral storage, and compares them with the exact `~/.agents/skills/use-*` target. It sends no repository or local skill content, persists no downloaded file without separate approval, and does not authorize any other network operation or mutation.

Explicitly invoking `release-qa` automatically queries the repository's configured Git remote and hosting Release metadata to establish remote `main`, tags, and the latest stable published release. Configured Git and hosting clients may use existing ambient authentication for private repositories, but the skill does not inspect, read, copy, print, persist, refresh, or reconfigure credential material, initiate authentication, upload source, or authorize network access from QA scenarios; unavailable access leaves the QA result incomplete.

Release QA stores bounded cluster reports, controlled-environment records, captured command output, and scenario material under a private `/tmp/release-qa.*` evidence root for user inspection. Reviewers must exclude credentials and unrelated source from that evidence. Aquarium reports the exact retained path; the user owns its later deletion, and ordinary completion does not remove it automatically.

Explicitly invoking `orca-review` performs local repository, Orca, skill, and CLI discovery and may start the installed Orca runtime before selection. Aquarium rejects remote or paired Orca routing and repository-local provider executables, then binds the verified local runtime identity and one outside-repository canonical provider executable path, digest, and observed version. An initial structured choice authorizes local preparation of a private read-only `/tmp` snapshot and exact Aquarium-supplied Task specification, but no Orca registration or source transmission. Aquarium then discloses a complete transmission-manifest digest covering every snapshot file, standalone Git metadata, and Aquarium Task byte it will supply. Only the second, final structured tool:model choice authorizes temporary registration of that exact folder and transmission of those manifested bytes plus the disclosed Orca-owned lifecycle preamble and identifiers through that same revalidated local runtime and executable. The final choice also discloses that this installed CLI is a same-user local process: Aquarium's manifest and instructions limit what Aquarium supplies and authorizes but do not form an operating-system read sandbox, so the CLI may technically access other files already readable by the user. Aquarium does not give the reviewer the original checkout path, and every reviewer must use the exact snapshot path selector rather than the mutable original checkout. After a settled worker is released and scope revalidation completes, Aquarium removes the exact registration and snapshot. Active, explicitly retained, unproven, or operationally incomplete workers keep them for later settlement, and failed release or cleanup can retain the exact local registration, snapshot, and coordinator evidence until manual recovery. Neither choice authorizes authentication, model listing, installation, updates, another provider, or intentional transmission of excluded working-tree or untracked content.

Explicitly invoking `test-setup` reads the selected local repository's test authorities and may run its bundled inspection script without executing project code. Applying an approved test-setup diff does not authorize tests that create containers, databases, external sandbox resources, paid requests, or other network or persistent effects; the skill discloses those effects and obtains separate approval before execution. It never opens known credential stores or credential-named paths, never emits raw authority contents or credential values in its report, and refuses an E2E target that cannot be verified as non-production. Inline values in ordinary source, test, manifest, or Make files may be read as part of structural inspection but are not reported verbatim.

Explicitly invoking `docs-setup` reads regular non-symlink tracked text plus non-ignored untracked text below discovered canonical documentation owners, as needed to inventory roles, roadmaps, identifiers, and references and verify an approved documentation diff before staging. It may run its bundled local inspector without executing project code or contacting a network. It excludes `.env*`, credential, authentication, key, secret, token, binary, oversized, ignored, and symlinked paths; reports category counts for all exclusions and paths only when a canonical authority or symlink exclusion makes the result unverifiable; and emits paths, line numbers, identifiers, allowlisted statuses, and structural findings rather than document contents. Applying an approved documentation diff does not authorize staging, commits, synchronization, publication, or project commands.

- Aquarium's trusted local commit hook receives the proposed shell command and working directory from Codex, resolves the local Git root, lists tracked paths, and reads up to two million characters from tracked roadmap candidates to detect lifecycle states. It writes no project state, stores no telemetry, and transmits none of that command, path, repository, or roadmap content over the network.
- Sanho can contact a configured documentation Git remote. Its selected-skill freshness comparison contacts GitHub automatically, and an approved `use-sanho` installation writes the verified four-file payload to a user-scoped Codex skill directory.
- Mulgae can transmit an explicitly preflighted review target to providers configured by the user and retains complete provider stdout and stderr in private local runtime artifacts. A selected Codex credential profile projects only its `auth.json` into a disposable local runtime; profile homes and credentials remain machine-local and must not be reported or committed. Its selected-skill freshness comparison contacts GitHub automatically, an approved `use-mulgae` installation writes four files below `~/.agents/skills/use-mulgae`, and an optional attached STDIO MCP process remains bound to the selected local repository. `dev-setup` does not run reviews, start the MCP server, capture a review target, invoke a provider, authenticate Codex, or transmit source.
- Orca Review uses the separately installed Orca application, CLI, and `$orca-cli` skill to create local Run, Task, Dispatch, terminal, lifecycle, and transcript state. The selected AI provider receives the disclosed review scope under its own account and data-handling policy; Aquarium reports bounded evidence and does not expose credentials, raw transcripts, provider payloads, or subagent reasoning.
- Lora installation contacts npm and GitHub and writes selected skills to the Codex user-global skill directory.
- Cursor Team Kit Deslop installation contacts GitHub and npm after separate approvals, resolves an exact upstream commit into ephemeral storage, and writes the upstream `SKILL.md` and MIT LICENSE to `~/.agents/skills/deslop`. Aquarium does not retain that source in its plugin distribution.
- Gaori stores local test logs and summaries under `.gaori/`; raw logs are intentionally unredacted and can contain sensitive process output. Its selected-skill freshness comparison contacts GitHub automatically, an approved `use-gaori` installation writes four files to a user-scoped Codex skill directory, and an optional attached STDIO MCP process remains bound to the selected local repository.
- Podway stores workspace configuration and local task history under `.podway/` and operates a same-user local daemon. It does not transmit source or evidence over the network; its selected-skill freshness comparison contacts GitHub automatically, and an approved `use-podway` installation writes four files below `~/.agents/skills/use-podway`.
- An explicitly approved `task-handler` or `epic-handler` plan handoff writes the approved Markdown plan once to `.podway/runtime/handoffs/<initial-session-id>/plan.md` with private local permissions. Aquarium does not create this file for ordinary execution or plan-only requests, transmit it, stage it, or commit it; Podway records only its local path, SHA-256, byte size, and media type. The owning handler retains it while the workflow may resume and removes only that exact temporary file after successful final closeout.
- Ouroboros may transmit only the source and document scope displayed in an explicitly approved Aquarium execution envelope when a selected upstream provider-backed operation requires it. The selected `ooo --version`, `ooo codex doctor`, `ooo mcp doctor --json`, and `codex mcp get ouroboros --json` diagnosis probes are local and read-only: they do not contact a provider, initiate authentication, or make a network request, though MCP diagnosis may inspect bounded local authentication-readiness metadata without exposing credential material. Aquarium setup never calls a provider, authenticates, transmits repository source, or starts an execution loop. Approved `uv` package installation, `ooo codex refresh`, and `ooo setup --runtime codex --non-interactive --mcp-mode auto` are separate mutations with separate approvals and may contact their documented package or runtime endpoints.

Those tools and services have their own data handling policies. The skills instruct Codex not to open known credential stores or credential-named paths and not to print, copy, or persist credential values. Structural inspection may incidentally read inline values in ordinary source, test, manifest, or Make files as disclosed above, but setup does not transmit repository source. Users should inspect proposed commands, capture sets, exclusions, and provider routing before approval.

Project configuration and ordinary runtime evidence remain in the locations owned by each tool. Ignored Mulgae, Gaori, and Podway runtime paths and identities are not durable repository authority and must not be copied into tracked documentation as execution logs. When an approved workflow has a concrete downstream need that code, tests, specifications, and Git history cannot satisfy, it may copy only reviewed bounded non-sensitive structured evidence into a tracked `aquarium.promoted-evidence/v1` package under `evidence/aquarium/` or one custom repository-relative tracked root named in the applicable repository `AGENTS.md` Project Configuration. Standard promotion excludes raw logs, excerpts, accepted reports, provider transcripts or prose, quotes, diagnostics, export bundles, credentials and credential paths, runtime or provider identities, timestamps, usernames, native-home or absolute paths, machine-specific paths, and Podway databases or history. This package is evidence, not central project state.

Aquarium does not bundle Lora, Ouroboros, or Cursor Team Kit skill or documentation sources. Approved installations obtain those sources directly from their official upstream repositories or packages and store them only in the owning user-scoped tool locations.

Aquarium procedures instruct agents to record bounded summaries, provider operation identifiers, revisions, exit statuses, paths, and digests in Podway rather than source contents, credentials, raw provider prompts or payloads, transcripts, generated documents, or full logs. Podway actor labels are correlation metadata, not authentication.
